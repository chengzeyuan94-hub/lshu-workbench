# L叔工作台 v0.1 深度复盘

日期：2026-08-25  
版本结论：`v0.1.0`  
发布形态：macOS-first、本地单用户、公开源码基线

## 1. 一句话结论

v0.1 已经从“小红书数据页”成长为一个有两条真实闭环的本地个人工作中枢：一条把四类工作来源压缩成当天最多五件重点任务并打印成本地排程小票；另一条把热点素材转成单篇或批量朋友圈并沉淀历史。它已经达到单用户本机 MVP 的定版标准，但不是远程 SaaS，也不应被包装成全平台、零配置的成熟产品。

## 2. 为什么现在定版

过去的开发经历了大量“功能可用—视觉回归—真实权限未通—再次返工”。继续追加功能的边际收益已经低于收口收益。当前最需要的是建立可追溯基线、冻结安全边界、分离私人数据与公共代码、让新用户能从干净环境启动。v0.1 的价值不是“所有连接器永远稳定”，而是产品骨架、核心数据模型和两条工作闭环已经成立。

## 3. 产品目标与核心任务

目标用户是同时经营内容、课程、产品与个人项目的单人创作者。其核心问题不是缺少工具，而是信息散落：待办在 Things，承诺在飞书，固定时间在 Calendar，工作痕迹在桌面，内容指标在小红书，灵感在新闻源，收支在记账软件。

v0.1 选择解决三个问题：

1. 今天到底发生了什么；
2. 今天真正值得完成哪几件事；
3. 内容与经营数据能否在一个本地界面形成行动。

因此产品不是“全量信息镜像”，而是“本地读取、统一口径、有限聚焦、可追溯输出”。

## 4. 信息架构

v0.1 固定为八个一级页面：

| 编号 | 页面 | 用户问题 |
|---|---|---|
| H-01 | 今日 | 当前环境、内容走势和最重要事项是什么？ |
| T-02 | 待办 | 四源今天数据如何压缩成可执行排程？ |
| F-08 | 财务分析 | 本周、本月、本年赚了多少、花了多少？ |
| C-03 | 内容表现 | 小红书账号和笔记表现如何？ |
| R-04 | 热点雷达 | 今天有什么素材、哪些值得转成朋友圈？ |
| K-05 | 知识大脑 | 本地知识库能否回答问题并辅助创作？ |
| S-06 | 扫描报告 | 电脑中有哪些工作线索和项目簇？ |
| S-07 | 设置 | 数据源、权限、隐私与 AI 边界是什么？ |

首页遵循“先环境、再走势、后行动”；待办遵循“同步今日数据、统一总览、规划今日排程”；热点遵循“素材、精选、生成、历史”。这三条顺序已经足够稳定，应在 v0.2 前冻结。

## 5. 两条核心闭环

### 5.1 今日工作闭环

```text
Things / 飞书 / Apple Calendar / 桌面
        ↓
标准化、checkpoint、证据与 DLP
        ↓
今天总览（行动项与固定事件）
        ↓
AI 最多选择 5 件主任务
        ↓
避开固定事件与过去时间
        ↓
本地 day plan + 打印小票
```

关键产品决策：

- Things“今天”1:1 进入，不经过 AI；
- Apple Calendar 是固定占位，不可移动；
- 飞书与桌面必须先判断是否存在本人行动意图；
- 普通聊天与文件变化进入来源摘要，不膨胀成待办；
- 每天最多五件主任务，固定事件不占名额；
- 排程只写本地草稿，外部日历写入默认禁止。

这条闭环已完成，但 AI 行动项的语义去重和“需确认”压缩仍是 v0.2 的第一质量问题。

### 5.2 内容生产闭环

```text
热点素材 → 精选 → 单篇/最多四篇批量生成
        → 只展示朋友圈正文 → SQLite 历史朋友圈
```

这一闭环是 v0.1 完成度最高的部分。模型的完整思考和调试信息不再进入主界面，单篇与批量结果均以最终正文为公开契约；成功结果持久化后能在自适应历史网格中回看。下一步应做编辑、复制、标签与去重，而不是继续增加生成入口。

## 6. 功能完成度

| 模块 | v0.1 结论 | 主要限制 |
|---|---|---|
| 今日 | 完成 | 天气受浏览器定位与外部服务影响 |
| 待办 | 主链路完成 | AI 语义去重、身份权限与错误文案仍需改进 |
| 财务 | 完成 | 当前只适配 MoneyCats 备份结构 |
| 内容表现 | 完成 | 依赖 OpenCLI 与目标账号配置 |
| 热点雷达 | 完成度高 | 实时素材与精选依赖不同外部服务 |
| 历史朋友圈 | 完成 | 暂无编辑、搜索、删除和标签 |
| 知识大脑 | 可用适配器 | 服务与知识数据不在本仓库 |
| 扫描报告 | 可用 | 必须显式授权目录，规则仍偏启发式 |
| 设置 | 可用 | 需要进一步统一活状态与历史状态文案 |

## 7. 体验与视觉复盘

已经形成识别度的部分：

- 黑白结构、直角 2px 黑框、橙色主操作、黄色提醒；
- 像素字体、像素图标和打印机/小票叙事一致；
- 首页、待办和内容页均建立了明确一级模块边界；
- 小票动画遵守“完整纸面从固定出票口下移”的物理模型；
- 手账排程把抽象 AI 结果变成可收藏、可打卡的对象。

反复返工暴露的教训：

1. 功能升级不能拆掉既有一级模块框架；
2. “高度一致”必须基于真实内容密度，而不是硬撑最小高度；
3. 动画应先定义物理模型，再写显隐与位移；
4. 响应式需要按容器宽度验收，不能只看浏览器宽度；
5. 主页面只回答用户问题，Prompt、Schema、权限快照和内部错误码应进入运行详情。

## 8. 工程架构

前端采用 React 18、TypeScript、Vite、React Router、Recharts 与本地像素资源；后端采用 Node.js 24、Express、better-sqlite3 与 TypeScript。macOS 原生能力通过 Things/JXA、EventKit Swift helper 和本机 CLI 适配器接入。

公开版生产启动只暴露一个 localhost 端口：Express 提供 API，并同源托管构建后的前端。开发时仍可使用 Vite 热更新。SQLite 运行目录与 `.env.local` 使用限制权限，所有连接器默认关闭。

核心工程优势：

- 数据统一落到可迁移的本地 SQLite；
- connector、AI 判断、today overview、排程与 UI 基本解耦；
- 对重复同步、错误降级、权限状态和外部写入有自动测试；
- OpenCLI/飞书使用参数数组执行，不拼接 shell；
- 外部模型输入经过裁剪、脱敏与预算限制。

主要技术债：

- `global.css`、`db.ts`、`index.ts`、热点页和待办页体积偏大；
- migration 分散在多个 schema 文件及直接 ALTER 逻辑；
- 用户品牌和部分业务文案仍与通用能力耦合；
- 缺少浏览器 E2E、axe、覆盖率门槛与真实 clean-install CI；
- Node 24、native SQLite、Swift helper 让部署比普通 Web 项目复杂；
- CLI 的上游返回结构变化仍可能打断真实联调。

## 9. AI 边界

AI 只承担两个有限职责：把飞书/桌面证据判断为行动项，以及从当天可排程事项中选出最多五件并给出时间偏好。Things 与日历的结构化事实不需要 AI；财务解析完全不经过 AI。

正确的 AI 契约必须满足：

- 输入只含脱敏、长度受限的信息；
- 输出必须通过版本化 JSON schema；
- 旧 Prompt 缓存不能污染新版本；
- 0 个行动项是合法业务结果，但必须来自一次合法响应；
- 模型思考过程不展示、不持久化为朋友圈正文；
- 用户能看到为什么选择/延后，而不是工程错误码。

## 10. 安全与隐私复盘

私人工作目录不能直接上传或整体压缩。它包含真实 `.env`、SQLite、数据库备份、日志、财务聚合、连接器标识、个人画像和大量验收截图。`.gitignore` 只保护 Git 跟踪，不能保护 `zip -r`。

v0.1 开源包因此采用白名单重建，而不是“删除几个文件后发布”：

- 不包含 `.env.local`、`backend/data`、日志、构建物或依赖；
- 不包含个人账号 ID、电脑用户名、绝对路径、工作画像或真实演示笔记；
- 不包含个人头像、参考照片、下载视频帧和旧验收截图；
- 用通用头像、虚构数据和中性工作画像替代；
- 所有连接器和 scheduler 默认关闭；
- 后端继续只绑定 `127.0.0.1`；
- 增加发布前隐私扫描与 CI 门槛。

这不是“清空私人数据库后复用”，而是从空 schema 创建新运行数据。

## 11. 许可证与资产

公开源码使用 MIT。Fusion Pixel 字体与 Pixelarticons 沿用各自附带许可证。个人 IP 头像、参考照、小红书截图、视频关键帧和私人知识库均不进入公开包。原先带第三方派生说明的两个轻量动效已在公开包中重写为独立实现，避免把受附加许可约束的组件误标成纯 MIT。

## 12. 为什么不以 Docker 作为 v0.1 一键部署

Docker 无法直接获得 macOS EventKit/TCC、Things Automation、iCloud MoneyCats、宿主浏览器登录态和本机 Feishu/OpenCLI 授权。为了端口映射改成 `0.0.0.0` 还会破坏当前无认证 API 的本地安全边界。

因此 v0.1 的正确“一键部署”是 macOS 本地安装：锁定 Node 24、安装两个 lockfile、构建前端、可选构建 Swift helper、单进程 localhost 启动。未来若做 Docker，只能先做连接器全关且有访问认证的演示核心。

## 13. v0.1 验收标准

发布前必须同时满足：

1. 后端与前端 TypeScript、测试和构建全部通过；
2. 从空数据目录启动，健康接口返回 `appVersion=0.1.0`；
3. 未配置凭证、未授权连接器时仍能打开界面且不主动外联；
4. 私密目录、数据库、日志、真实账号与个人绝对路径在源码包和归档中均为 0；
5. `.env.local` 为 0600，data/runtime 目录为 0700；
6. 只监听 localhost；
7. Calendar、Things、OpenCLI、飞书、知识库缺失时均诚实降级；
8. License、隐私、安全、第三方许可和变更记录齐全；
9. 归档附 SHA-256；
10. GitHub 推送前由用户确认公开仓库名称和目标账号。

本次发行候选的实测结果：

- 后端 Vitest 4.1.11：36 个测试文件，234/234 通过；
- 前端 Vitest 4.1.11：9 个测试文件，33/33 通过；
- 后端 TypeScript、前端 TypeScript 与 Vite 8.2.2 构建通过；
- 两个 lockfile 的 `npm audit` 均为 0 个已知漏洞；
- 空临时数据目录启动成功，健康接口返回 `appVersion=0.1.0`；
- 首页由同一 localhost 后端成功托管；
- Things、飞书、桌面、Calendar、热点自动抓取和 AI 在全新配置中均为关闭；
- 临时数据目录权限为 0700，SQLite 文件权限为 0600；
- 白名单树的内置隐私扫描通过。

## 14. v0.2 路线图

P0 产品质量：

1. AI 行动项语义去重与“需确认”压缩基准；
2. 统一设置页“本轮状态/上次成功/权限阻塞”口径；
3. 历史朋友圈编辑、复制、搜索、标签与删除；
4. 数据导出、保留周期与一键清空；
5. Playwright 核心流程 E2E 与自动无障碍检查。

P1 工程质量：

1. 拆分大 CSS、路由入口、数据库初始化和热点页；
2. 建立正式 migration registry；
3. 工作画像改为本机 untracked 配置；
4. 增加发布 SBOM、依赖审计和 macOS clean-install runner；
5. 连接器 SDK 与统一状态模型。

P2 平台化：

1. 可换品牌、头像、配色和工作画像模板；
2. 更多任务、日历和记账适配器；
3. 有认证的只读远程查看模式；
4. 全局外部请求开关与统一成本预算。

## 15. 最终判断

冻结 v0.1 是正确选择。产品价值已经出现，接下来最重要的不是再塞入口，而是提高行动判断可信度、把数据治理补齐，并确保任何新用户拿到的是一个真正空白、诚实降级、可安全安装的版本。公开包可以作为首个 Git 历史基线；私人工作目录继续保留真实配置和数据，但永远不应成为发布源。
