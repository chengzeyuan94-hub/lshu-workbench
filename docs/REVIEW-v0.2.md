# L叔工作台 v0.1 公开版复盘

日期：2026-08-26  
适用范围：GitHub 公开发行版 `v0.1.0`

## 1. 结论

v0.1 已经从单一的小红书数据页，发展为一套面向个人创作者的本地工作中枢。它把“今天做什么、内容表现如何、热点能否转成内容、经营数据是否健康”放进同一套产品语言中，并形成两条可被持续使用的核心闭环。

当前版本适合作为：

- macOS 本地单用户工作台；
- 本地优先、连接器按需开启的产品基线；
- 二次开发和自定义适配器的开源起点；
- 像素打印机与小票式工作流的设计参考。

当前版本不应被描述为：

- 零配置、全平台的成熟 SaaS；
- 所有外部连接器永远可用的托管服务；
- 可以直接暴露到公网的无认证后端；
- 包含作者私人数据、账号、凭证或知识库的完整镜像。

## 2. 产品定位

目标用户是同时经营内容、课程、产品和个人项目的单人创作者。其主要问题不是缺少工具，而是信息分散在任务应用、聊天、日历、桌面、小红书、新闻源、知识库和记账软件中。

工作台选择解决三个问题：

1. 今天发生了什么；
2. 今天最值得完成哪几件事；
3. 内容与经营数据能否回到同一个行动界面。

因此，产品的原则不是“全量复制所有原始信息”，而是“本地读取、统一口径、有限聚焦、可追溯输出”。

## 3. 信息架构

公开版保留八个一级页面：

| 编号 | 页面 | 主要职责 |
|---|---|---|
| H-01 | 今日 | 时间、天气、内容走势和今日事项 |
| T-02 | 待办 | 汇总来源、确认事项和本地排程 |
| F-08 | 财务分析 | 本周、本月、本年收支摘要 |
| C-03 | 内容表现 | 小红书账号与笔记表现 |
| R-04 | 热点雷达 | 实时素材、精选和内容草稿 |
| K-05 | 知识大脑 | 外部本地知识库适配 |
| S-06 | 扫描报告 | 授权目录中的项目与工作线索 |
| S-07 | 设置 | 连接器、权限、隐私和运行状态 |

一级结构在 v0.2 前应保持稳定。下一阶段的重点不是继续增加页面，而是提高状态可信度、真实连接稳定性和可维护性。

## 4. 核心闭环

### 4.1 今日工作

```text
Things / 飞书 / Apple Calendar / 授权桌面目录
        ↓
本地标准化、来源证据、时间窗口与隐私裁剪
        ↓
今天总览
        ↓
最多选择 5 件主任务
        ↓
避开固定事件与过去时间
        ↓
本地排程草稿与小票
```

关键产品规则：

- 结构化任务和固定日历事件不需要模型重新判断；
- 聊天与桌面线索必须先判断是否存在行动意图；
- 普通信息只进入来源摘要，不能膨胀为大量待办；
- 每天最多五件主任务，固定事件不占主任务名额；
- 默认只生成本地草稿，外部日历写入保持关闭；
- AI 输入必须经过裁剪、脱敏、预算限制和版本化 Schema。

### 4.2 内容生产

```text
热点素材 → 精选 → 单篇或批量生成
        → 只展示最终朋友圈正文
        → 历史朋友圈
```

生成页不应展示模型思考过程、调试信息或原始响应。后续增强应集中在编辑、复制、搜索、标签、删除和相似内容去重。

## 5. 视觉与交互

工作台已经形成稳定的视觉身份：

- 白色背景与近黑结构线；
- 橙色主操作、黄色提醒；
- 像素字体、像素图标和硬边框；
- 打印机、票据和手账排程；
- 内容层级优先于装饰。

最重要的设计经验是：功能升级不能破坏原有一级模块框架；动画要先定义物理模型；响应式应按内容容器验收；工程状态和内部错误应进入运行详情，而不是铺满主页面。

## 6. 本地优先与隐私边界

公开版遵守以下边界：

- 后端默认只绑定 `127.0.0.1`；
- 所有连接器和 scheduler 默认关闭；
- 外部日历写入默认拒绝；
- 私人 SQLite、日志、环境变量、聊天、财务原始数据和知识库不进入仓库；
- 模型只接收显式允许、长度受限且经过隐私处理的输入；
- 缺少授权或凭证时必须诚实降级；
- 发布包通过文件白名单重建，而不是复制私人工作目录后再删除文件。

任何使用者都应自行创建凭证并完成系统权限授权。示例数据只用于展示界面，不代表真实连接器已建立。

## 7. 工程结构

前端采用 React、TypeScript、Vite 与 React Router；后端采用 Node.js、Express、TypeScript 与 SQLite。macOS 原生能力通过只读脚本、CLI 或原生 helper 适配。

当前优势：

- 本地 SQLite 作为统一持久层；
- 连接器、AI 判断、当天总览、排程与 UI 基本解耦；
- 对重复同步、权限失败、旧数据保留和外部写入有明确边界；
- 发布版从空数据目录启动；
- 原生依赖和 Node 版本被固定。

主要技术债：

- 部分页面、样式、入口和数据库初始化文件偏大；
- migration 与 scheduler 仍需进一步集中治理；
- 缺少完整浏览器端到端和自动无障碍门禁；
- 外部 CLI 与第三方接口变化仍可能影响真实接入；
- 运行生命周期、数据保留和错误可观测性需要统一。

## 8. 验证原则

自动化测试、TypeScript 和构建通过，是代码质量门槛，但不等于外部连接器已经完成真实联调。

每次发行必须分别报告：

1. 自动化测试结果；
2. 空配置启动结果；
3. 真实连接器结果；
4. 外部权限阻塞；
5. 仅由测试夹具验证的能力；
6. 未完成项。

不得把历史成功、缓存命中或 fixture 写成“本轮真实成功”。

## 9. v0.2 优先级

### P0：可信与安全

1. 统一“本轮状态、上次成功、缓存与权限阻塞”的展示；
2. 加强数据迁移、目录边界和模型输入的回归门禁；
3. 建立可控的数据保留与备份策略；
4. 确保启动、停止、异常退出和调度都有明确生命周期；
5. 完成关键连接器的真实脱敏验收；
6. 核心列表、页签和抽屉支持完整键盘操作。

### P1：工程质量

1. 拆分大页面、大样式、入口和数据库模块；
2. 建立正式 migration registry；
3. 增加 Playwright、无障碍检查和覆盖率门槛；
4. 统一连接器状态、URL 策略和安全错误 DTO；
5. 增加数据导出、按来源归档和一键清空；
6. 让个人品牌与工作画像成为本机 profile，而不是通用代码默认值。

### P2：平台化

1. 更多任务、日历与记账适配器；
2. 可替换品牌、头像、配色和工作画像；
3. 有认证的远程只读查看模式；
4. 慢网首屏、字体子集与路由拆包；
5. 时区与地区配置完善。

## 10. Definition of Done

下一版只有同时满足以下条件，才能标记为稳定版：

- 界面状态与真实运行结果一致；
- 权限失败、网络失败、空结果和缓存结果可以区分；
- 数据迁移不会丢失历史记录；
- 扫描不会越过用户授权范围；
- 模型输入与用户告知一致；
- 数据备份和保留周期有上限；
- 工作台可以可靠启动和停止；
- 核心流程可使用键盘完成；
- 前后端测试、TypeScript、构建、端到端和隐私检查全部通过；
- 发布包不包含私人数据、绝对路径或真实凭证。

## 11. 最终判断

v0.1 值得作为首个公开基线保留。它已经建立了清晰的产品方向和独特的视觉语言。下一步最有价值的工作不是继续叠加入口，而是把可信度补齐：成功必须有真实证据，失败必须诚实表达，所有进入模型或公开页面的数据都必须可解释、可控制。

> v0.1 是产品与代码基线；v0.2 聚焦可信、稳定、安全与可维护性。
